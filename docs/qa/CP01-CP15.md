## Temuan audit awal — sudah ditutup

### QA-01 — P2: Media dapat memulai ulang konten yang diarsipkan

PRD §8.4 menetapkan `archived → draft baru` hanya oleh Admin. Artikel membedakan `restart-archived` dari revisi publik dan membatasi aktornya. Pages dan shared reviewed engine justru memakai `create-revision` untuk kedua sumber dan tidak memeriksa Admin ketika sumbernya archived.

Reproduksi pada database uji baru: buat dan terbitkan About Page/Event milik Media; tarik publikasi sebagai Admin, tanpa revisi kerja tersisa; kirim `create-revision` sebagai Media dengan lockVersion dan expectedRevisionId terbaru. **Keduanya menghasilkan HTTP 200; seharusnya 403.** Revisi baru benar-benar dibuat. Media tetap tidak dapat menerbitkan sendiri; temuan ini tidak membuktikan bypass approval publikasi.

Lokasi: `src/editorial/page-commands.ts:28–44`, `src/editorial/reviewed-commands.ts:35–50`, serta tombol pada `PageActions.tsx:81` / `ReviewedActions.tsx:83`. Reproduksi langsung dilakukan untuk Pages dan Events. Periode, divisi, pengurus, riset dan rekrutmen memakai fungsi shared reviewed yang sama; dampak pada jenis tersebut diturunkan dari jalur kode bersama, bukan klaim bahwa setiap jenis sudah direproduksi satu per satu.

Perbaikan: pisahkan restart arsip atau tambahkan pemeriksaan Admin ketika sumber bukan publikasi aktif; pertahankan hak Media membuat revisi dari publikasi aktif. Tambahkan tes negatif Media dan positif Admin, tanpa perubahan pointer/audit ketika request ditolak.

### QA-02 — P2: pengarsipan revisi kerja belum tersedia pada Pages/shared reviewed

PRD §8.4 menyediakan pengarsipan `draft/revision_required → archived` oleh Admin, tanpa menarik publikasi sebelumnya (§8.5). Kontrak tugas juga mewajibkan collection editorial baru mengikuti kontrak yang dibuktikan pada T025. Artikel menyediakan `archive-revision`; whitelist command dan UI Pages/shared reviewed tidak menyediakannya.

Reproduksi: buat draft Homepage dan Event, lalu panggil `archive-revision` sebagai Admin dengan versi/revisi yang valid. **Keduanya HTTP 400 “Unknown … action”; seharusnya operasi tersedia dan berhasil.** Tombol untuk tindakan ini juga tidak tersedia. Penghapusan draft merupakan tindakan berbeda dan bukan pengganti mengarsipkan revisi konten yang sudah memiliki riwayat publikasi.

Lokasi: `src/editorial/page-commands.ts:22`, `src/editorial/reviewed-commands.ts:30` dan komponen aksi terkait. Perbaikan: implementasikan transisi Admin-only, pemeriksaan tidak ada pending review, pelepasan working pointer, audit atomik, serta pelestarian public pointer dan referensi historis. Uji bahwa versi publik/aset lama tetap tersedia dan pending review wajib dibatalkan dahulu.

### QA-03 — P2: CTA dari blok Pages masih mengajak mendaftar setelah deadline

T042 dan PRD §8.8 mengharuskan aturan waktu berlaku pada halaman yang sudah terbuka. Panel rekrutmen memakai LiveRegistration dan lulus. Akan tetapi blok Pages `cta` dengan URL `/rekrutmen` hanya difilter saat render server, lalu menjadi Link statis melalui PageSections.

Reproduksi: terbitkan kampanye enabled dengan waktu tutup 15 detik ke depan; terbitkan homepage berisi hero serta CTA berlabel “Daftar kampanye QA”, URL `/rekrutmen`; buka homepage sebelum tutup dan biarkan terbuka. Pada deadline, API mengembalikan `canRegister:false` dan tombol utama “Daftar sekarang” hilang, tetapi **satu link CMS “Daftar kampanye QA” tetap terlihat; seharusnya nol**. Screenshot `artifacts/QA-CP15-stale-cta.png` telah diinspeksi. Link tersebut menuju halaman informasi internal; pembatasan pendaftaran pada halaman tujuan tetap bekerja. Masalahnya adalah CTA yang masih mengajak mendaftar ketika status sudah ditutup.

Lokasi: `src/app/(public)/page.tsx:12,40` dan `src/components/public/PageSections.tsx:10`. Perbaikan: alirkan seluruh CTA pendaftaran melalui state/deadline yang sama atau gunakan tipe blok khusus; jangan hanya menguji panel bawaan. Uji deadline, disable/withdraw, perubahan kampanye, dan pemulihan tab pada kedua sumber CTA.

## Hasil eksekusi audit awal — sebelum perbaikan

- Suite utama `pnpm test:all`: **32 unit, 57 integration, 32 e2e lulus**, tanpa retry. Seluruh migration diterapkan pada DB PostgreSQL lokal baru milik run, audit bertahan setelah restart dan cleanup terjaga. Bukti lokal: `artifacts/qa-cp01-cp15-baseline.log`.
- Probe tambahan pada build produksi/DB terisolasi lain: **3 gagal sesuai ketidaksesuaian di atas, 1 lulus**. Kegagalan adalah assertion bisnis (200 vs 403, 400 vs 200, satu CTA vs nol), bukan error setup. Bukti lokal: `artifacts/qa-cp01-cp15-probes.log`.
- Probe akun lulus pada schema terkini: sesi nonaktif ditolak dan tidak hidup lagi sesudah reaktivasi; reset menolak password/cookie lama; kegagalan INSERT audit membatalkan perubahan akun; dua Admin yang menurunkan role sendiri menghasilkan **200/409**, tersisa satu Admin aktif. Tidak ada password fixture dalam snapshot audit.
- Mutation check membalik syarat konfirmasi URL rekrutmen dalam salinan modul; tes unit yang sama mendeteksinya. Source aplikasi tidak diubah. Ini pembuktian terarah, bukan skor mutation seluruh proyek.
- Lint, TypeScript dan build produksi akhir **lulus**. Arsip source probe sempat ikut terbaca oleh typecheck ketika berekstensi `.ts`; arsip dipindahkan menjadi `.ts.txt`, lalu typecheck/build diulang dan lulus. Tidak ada suppressions, perubahan tsconfig atau perubahan source aplikasi untuk mengatasi berkas QA tersebut.
- Supabase read-only: **15 migration, satu akun, nol artikel/pengurus/riset/event/kampanye**. `anon` dan `authenticated` tidak memiliki USAGE schema payload. Delapan tabel audit tidak dapat di-UPDATE/DELETE oleh role runtime. `pnpm db:check` membuktikan TLS klien encrypted/authorized true dan role gibei_runtime; batas internal pooler tetap mengikuti laporan T005.
- Audit dependency saat ini: critical **0**, high **0**, moderate **3**, low **1**; rincian lokal `artifacts/qa-cp01-cp15-dependencies.json`. Temuan lama tersebut tetap masuk T053, tidak disembunyikan atau diperbaiki dengan upgrade di luar lingkup QA ini.

Probe sementara hanya disalin ke `tests/e2e/qa-cp-audit.spec.ts` selama run terarah dan dihapus melalui finally setelahnya. Source probe disimpan lokal pada `artifacts/qa-cp-audit.spec.ts.txt`; suite utama tidak ditambah assertion yang membenarkan perilaku salah dan aplikasi tidak diubah untuk meloloskan tes. Dua database/cluster uji dibersihkan; tidak ada reset/fixture pada Supabase.
