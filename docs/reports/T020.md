# T020 — Penghapusan aman dan revoke darurat

Selesai 31 Oktober 2026. Endpoint Admin `POST /api/media/:key/manage` menerima `{ action: "revoke" | "delete", note }`. Alasan wajib; identitas/role dibaca ulang dalam transaksi dengan lock editorial. Revoke menutup file asli, thumbnail, HEAD, range dan conditional request, termasuk untuk Admin. Respons memuat referensi terdampak, reader publik menampilkan `available:false`, URL null dan fallback. Versi file tidak dapat diganti atau dipulihkan melalui update generik.

Delete ditolak 409 beserta daftar referensi dari semua revisi, manifest review historis dan ledger konfigurasi privat. Ledger `asset-config-references` hanya menahan penghapusan; ia tidak memberikan izin publik. Site Settings belum diimplementasikan: T027 wajib memperbarui ledger secara atomik dengan versi konfigurasi dan memakai reader izin konfigurasi yang sesuai. API generik tidak dapat membuat/mengubah ledger.

Untuk aset tanpa referensi, transaksi menyimpan tombstone `deleted` dan audit sebelum menghapus file dari direktori UUID yang diverifikasi. Kegagalan audit membatalkan perubahan dan mempertahankan file. Kegagalan pembersihan fisik mengembalikan `cleanupPending:true`, mencatat warning tanpa secret, dan file tetap tidak dapat diakses. Admin dapat mengulang delete pada key yang sama sampai cleanup berhasil. Tidak ada worker/background retry otomatis.

Perintah `delete-draft` memakai reason, expected lock version dan revision ID. Hanya Admin dapat menghapus draft belum pernah terbit, tanpa review pending atau referensi masuk dari revisi/manifest lain. Penghapusan berupa tombstone: revisi diarsipkan, pointer kerja dikosongkan, slug dilepas dan slug awal dicatat pada audit. Artikel hilang dari list/detail/editor dan tidak dapat dihidupkan kembali lewat PATCH/command, sedangkan audit/riwayat tetap disimpan. Konten pernah terbit tetap harus memakai withdraw/archive.

**Bukti akhir batch T011–T020:** 20 unit, 30 integration dan 18 Chromium e2e lulus, bersama pemeriksaan Local API, guarded reset dan cleanup database/file uji. Tes T020 mencakup setiap jenis referensi, role, alasan, file lama, fallback, review setelah revoke, rollback audit serta junction filesystem yang sengaja ditolak guard dan retry cleanup. Lint, TypeScript, instalasi offline frozen-lockfile dan build produksi lulus. Migrasi `20261031_070403_safe_deletion` aktif pada Supabase; table/column terkonfirmasi, anon tetap tanpa USAGE schema, runtime tidak dapat UPDATE audit, artikel pengembangan tetap nol.

Probe produksi lokal 3200 lulus login/logout, revoked session, HttpOnly/SameSite, Origin, blok first-register dan GraphQL. Reader list 200, slug hilang 404, parameter tak dikenal 400, semuanya no-store. Dev pengguna 3000 tetap merespons 200. `db:check` membuktikan client TLS encrypted/authorized; batas TLS internal pooler ke database tetap dicatat seperti T005.
