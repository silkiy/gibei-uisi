# Bukti T005 — PostgreSQL Supabase

Tanggal: **26 Oktober 2026**, Asia/Jakarta. Status: **T005.1–T005.3 selesai**. Proyek: `lgqnxvldjqzgbfyxqonx` (gibei-uisi, region ap-northeast-1). T005.1 memverifikasi akses/koneksi/TLS; T005.2 menyiapkan fondasi role/schema dan migration; T005.3 membuktikan transaksi, persistensi dan regresi.

## Kondisi awal dan perubahan

Pemeriksaan integrasi menemukan proyek ACTIVE_HEALTHY, PostgreSQL **17.11**, rilis managed **17.11.0.003**. Sebelum migrasi, `public`/`payload` tidak memiliki tabel aplikasi; schema `payload`/`gibei_meta` dan role `gibei_runtime`/`gibei_migrator` belum ada. Fondasi diterapkan pada namespace baru yang kosong dalam proyek ini; tidak membuat branch berbayar atau mengubah tabel layanan Supabase.

Migration `database_foundation` berhasil diterapkan melalui integrasi Supabase dan tercatat dengan versi **20261026101710**. Berkas lokal `supabase/migrations/20261026101710_database_foundation.sql` diselaraskan dengan history remote. CLI Supabase **2.122.0** digunakan untuk membuat berkas awal sesuai konvensinya. Migration ini hanya infrastruktur; schema/tabel CMS Payload tetap mengikuti T006.

Schema `payload` dan `gibei_meta` dimiliki role migrasi. Runtime mendapat USAGE dan operasi data yang ditentukan; tidak mendapat CREATE schema/table atau akses Auth. Role runtime/migrasi LOGIN dengan password acak terpisah, tanpa SUPERUSER/CREATEDB/CREATEROLE/REPLICATION/BYPASSRLS. Password hanya dipasang melalui koneksi lokal, tidak disimpan dalam SQL/history migration atau Git. `.env.local` kini memakai role runtime, ditambah MIGRATION_DATABASE_URL untuk migrasi; URL admin awal tidak dipakai sebagai koneksi aplikasi.

Driver **pg 8.23.1** dipatok pada package.json dan lockfile. Skrip pemeriksaan server berada di `scripts/database/`; tidak ada endpoint database publik. Pool maksimal tiga koneksi dengan timeout terbatas. `PAYLOAD_SECRET` yang sudah dikonfigurasi dipertahankan di `.env.local` dan lolos validasi dasar panjang/non-placeholder, tanpa menampilkan nilainya. CMS belum menggunakannya sampai T006.

## TLS dan koneksi aktual

URL API HTTPS awal ditolak; setelah pengguna mengisi connection string PostgreSQL, koneksi memakai **Session pooler port 5432**. CA diunduh dari endpoint yang tercantum pada [source resmi Supabase Studio](https://github.com/supabase/supabase/blob/master/apps/studio/hooks/custom-content/custom-content.json). Fingerprint SHA-256 CA:

`80:70:25:AD:50:D4:ED:21:9D:2C:9C:7D:29:9C:00:4F:82:4E:B0:0C:F7:F6:5A:FE:F6:07:D0:7B:72:E6:CA:FA`

Client TLS terbukti encrypted=true dan authorized=true, dengan verifikasi hostname/CA tetap aktif. `pg_stat_ssl` backend melaporkan **false** untuk leg internal Session pooler → PostgreSQL. Ini tidak mengubah bukti TLS localhost → pooler, tetapi **bukan TLS end-to-end**. SSL enforcement proyek tidak diubah/direboot; pengaturan internal tersebut tetap masuk tinjauan produksi. [Panduan resmi SSL enforcement](https://supabase.com/docs/guides/platform/ssl-enforcement).

## Temuan yang tetap terbuka

Advisor security sebelum/sesudah T005 melaporkan dua warning pada fungsi bawaan `public.rls_auto_enable()` (EXECUTE untuk anon dan authenticated); tidak ada warning baru pada schema fondasi. Pemeriksaan katalog menunjukkan fungsi bertipe event_trigger. Fungsi bawaan tidak diubah, dan kemampuan eksploitasi RPC tidak diasumsikan. T053 harus meninjau dan menutup/menjelaskan temuan ini sebelum menyatakan audit keamanan lulus. [Remediasi anon](https://supabase.com/docs/guides/database/database-linter?lint=0028_anon_security_definer_function_executable), [remediasi authenticated](https://supabase.com/docs/guides/database/database-linter?lint=0029_authenticated_security_definer_function_executable).

Adapter Payload 3.92.0, schemaName experimental, migration collection, users dan login **belum dibuktikan** oleh T005; pekerjaan tersebut menjadi T006. Runtime tidak boleh menjalankan schema push otomatis pada hosted database. Panduan operasi dan pemulihan credential ada di [setup](../setup.md).

**T006 siap dikerjakan.** T005 tidak menyatakan CMS, workflow editorial atau deployment produksi telah selesai.
