# T008 — Harness uji izin dan browser

Tanggal: 30 Oktober 2026. Acuan PRD §14.2/§16. Lingkup dibagi menjadi T008.1 (runner/unit/isolasi), T008.2 (database dan fixture API), T008.3 (Playwright/verifikasi/dokumentasi) karena melampaui lima berkas.

## Hasil

- `test:unit` menggunakan Node test runner, mencakup kebijakan akun, konfigurasi Supabase dan penjaga target test. Tidak memerlukan database.
- `test:integration` dan `test:e2e` membuat database PostgreSQL baru bernama `gibei_test_<run-id>`, role migrator/runtime terbatas, secret/password acak, marker run, migration Payload asli dan fixture satu Admin/dua Media. Media dibuat lewat API Admin, bukan melewati kontrol akun.
- Request anonim dan terautentikasi tersedia di tests/support/http.mjs. Playwright menyediakan context browser terpisah bagi Admin, Media A dan Media B; tidak menggunakan profil pribadi atau session tersimpan.
- Server test memakai build produksi pada `.next-test`, tsconfig khusus dan port acak loopback; server utama 3000 serta `.next` tidak digunakan. Launcher mengembalikan perubahan import yang dibuat Next pada next-env.d.ts jika perubahan tersebut sesuai pola yang dikenal.
- Reset data hanya dilakukan setelah URL loopback/nama database/role/marker cocok. Reset berjalan dalam transaksi satu client, membersihkan tabel aplikasi dan mempertahankan tabel migration. Setelah suite selesai, jumlah users dan audit adalah nol, lalu cluster/database milik run dihentikan dan dihapus. Kegagalan tes juga telah melalui cleanup.

## Bukti

- **10 unit test lulus**, termasuk penolakan URL remote/Supabase, database postgres, run ID berbeda dan target reset tanpa marker/role yang tepat. Tes penjaga semula gagal sebelum implementasi tersedia.
- **3 integration test lulus:** request anonim ditolak, Admin melihat tiga akun, masing-masing Media hanya melihat satu akun sendiri dan tidak membaca akun Media lain; eskalasi role/audit ditolak; logout membatalkan sesi pada request berikutnya.
- Integration dijalankan pada PostgreSQL **17.11** native, database baru terpisah dari Supabase. Migration `20261030_093751_cms_auth` dan `20261030_153435_account_controls` berhasil diterapkan; fixture roles=admin/media/media dan guarded reset lulus.
- **3 e2e test lulus** dengan Chromium proyek: halaman publik dan redirect CMS anonim; pengelolaan akun/login/logout Admin tanpa pageerror; dua Media pada context berbeda hanya melihat nama akunnya dan tidak mempunyai aksi create. Durasi suite browser 11,5 detik. Database baru kedua juga lulus guarded reset dan cleanup.
- Build test adalah hasil produksi Next 16.4.2. Dependency Playwright Test/Core 1.64.1 dipatok dalam lockfile; browser Chromium 156.0.8078.4 diunduh melalui installer resmi Playwright. Paket baru tidak memiliki install scripts; pemasangan memakai ignore-scripts dan frozen offline install berhasil.
- Audit seluruh dependency dan prod diperiksa: critical=0, high=1, moderate=1, low=1, sama dengan temuan T006/T007. GraphQL tetap nonaktif; temuan lama tidak dinyatakan selesai.

## Penyesuaian yang terbukti perlu

Docker Desktop terpasang tetapi engine Linux tidak dapat dihubungi; startup aplikasi/CLI kembali berhenti. Tidak mengubah konfigurasi Windows/WSL atau melakukan reset Docker secara manual. Backend Docker disiapkan dengan image resmi yang dipatok digest, tetapi belum diverifikasi runtime pada mesin ini. Bukti kelulusan memakai backend PostgreSQL native resmi, tanpa memasang service sistem. Sumber, hash artefak, keterbatasan tanda tangan binary dan prosedur setup dicatat pada [panduan pengujian](../testing.md).

Reset awal yang mencoba membuat ulang schema memerlukan privilege CREATE database yang sengaja tidak dimiliki migrator. Reset diubah menjadi truncate data aplikasi dengan guard dan transaksi, mempertahankan batas role. Kegagalan startup/tes tidak meninggalkan cluster uji.

Smoke browser pertama menunjukkan selector perlu mengikuti accessible name `Create new User` dan kolom Name. Selector dikoreksi berdasarkan snapshot DOM nyata, tanpa mengganti kontrol izin, menambah retry atau melewati tes. Log lokal disimpan di artifacts/test-run.log dan output browser di test-results, keduanya diabaikan Git. Trace/video/storageState dimatikan agar token/password tidak ikut rekaman jaringan.

Tes logout juga menunggu form login muncul sebelum menavigasi kembali ke CMS: logout Payload adalah client effect, sehingga navigasi terlalu dini membatalkan request tersebut. Tidak menambahkan jeda tetap atau melonggarkan pemeriksaan sesi. Metadata akun Supabase sebelum/sesudah sama (fingerprint `13366ba1e2812154b6ec452988b1e60c`), tetap satu Admin aktif. Folder cluster sementara kosong setelah cleanup; server utama 3000 tetap terpisah.

Pemeriksaan akhir `lint`, `typecheck`, build produksi normal, `test:cms` dan `db:verify` lulus. Frozen offline install dengan install scripts dinonaktifkan juga lulus. Bukti screenshot Admin dengan tiga fixture ditinjau pada test-results/admin-users.png. T001–T008 ditandai selesai, T009 siap dikerjakan; CP-03 tetap menunggu T009.

## Batas

Harness ini adalah fondasi uji dan smoke akun/CMS. Fixture editorial, upload privat, approval, publikasi, konflik dan cache belum dibuktikan; tes berikutnya ditambahkan sesuai tugas terkait. T009 adalah fondasi visual berikutnya. Tidak ada deployment/push atau perubahan kredensial akun pengembangan. Perubahan whitespace pengguna pada migration T005 tetap di luar pekerjaan ini.
