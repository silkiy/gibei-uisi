# Bukti T006 — Payload dan login CMS

Tanggal: **30 Oktober 2026**, Asia/Jakarta. Status: **T006.1–T006.3 selesai**: integrasi/migrasi, bootstrap/autentikasi, dan verifikasi. Lingkup ini tidak mencakup pengelolaan akun lengkap T007 atau workflow editorial T010–T025.

## Implementasi

Payload, integrasi Next dan adapter PostgreSQL **3.92.0** dipasang bersama GraphQL 16.14.2, Sharp 0.35.5 dan runner TypeScript tsx 4.23.15. Next tetap 16.4.2. Config memakai schema **payload**, push=false dan disableCreateDatabase=true; transaksi adapter tetap aktif. Runtime menggunakan gibei_runtime, sedangkan perintah migration memakai MIGRATION_DATABASE_URL/gibei_migrator.

Migration Payload `20261030_093751_cms_auth` berhasil diterapkan dan berstatus **Ran: Yes, batch 1**. Migration membuat users, sessions, preferences, KV, lock records dan history Payload hanya pada schema privat. Migration infrastruktur Supabase T005 tetap terpisah; tidak menjalankan reset/drop/fresh atau mengubah schema layanan Supabase. Perubahan whitespace pada migration T005 yang sudah ada sebelum tugas ini dibiarkan.

Route group `(payload)` menggunakan layout/CSS Payload terpisah dari `(public)`. Tipe dan import map dihasilkan melalui CLI versi terpasang. Path CA pada config aplikasi dibatasi statis ke `certs/supabase-prod-ca-2021.crt`; pembacaan path environment arbitrer sempat menimbulkan warning tracing seluruh proyek, lalu diperbaiki. Build akhir tidak memiliki warning tracing tersebut. Telemetry Payload dinonaktifkan.

## Akun dan batas keamanan

| Ancaman | Kontrol dan bukti |
|---|---|
| Mengambil alih Admin pertama melalui web | POST first-register selalu 403, route create-first-user 404. Hook beforeChange juga memeriksa hak create meskipun Local API memakai overrideAccess. Sebelum bootstrap, request anonim ditolak dan jumlah users tetap nol. |
| Memalsukan izin bootstrap lewat JSON | Capability berupa Symbol server-only, tidak dapat dibentuk dari JSON context. Dua tes kebijakan lulus, termasuk Media/Admin nonaktif dan context palsu. |
| Bootstrap menggandakan/menimpa akun | Advisory lock PostgreSQL dan pemeriksaan jumlah akun sebelum create. Bootstrap ulang dua kali mengembalikan skip, exit 0; jumlah akun tetap satu. Race paralel belum menjadi hasil uji yang diklaim. |
| Password tetap atau tersimpan mentah | Password Admin demo dibuat acak 24 byte, hanya disimpan pada BOOTSTRAP_ADMIN_PASSWORD di `.env.local`. Database memiliki hash/salt, bukan field password mentah; hash/salt/password tidak muncul di respons login. |
| Pembacaan privat tanpa sesi | Anonim GET/POST users ditolak 403; browser diarahkan ke login. Admin aktif dapat masuk/read; tipe role admin/media dan status active/inactive tersedia. Update/delete akun sengaja ditutup sampai T007. |
| Replay sesi sesudah logout | useSessions=true; login/logout dan penolakan cookie sesi lama setelah logout dibuktikan melalui API. Token tidak dikembalikan pada JSON login. |
| Permintaan lintas origin | Daftar CORS/CSRF eksplisit serta guard Origin pada mutasi REST; uji logout dari origin asing ditolak 403. Pemeriksaan CSRF menyeluruh tetap T053. |
| Kebocoran sesi/email reset | Cookie HttpOnly, SameSite=Lax, masa sesi 7200 detik. Secure aktif jika SERVER_URL HTTPS; HTTP hanya baseline loopback. Endpoint pemulihan email dinonaktifkan dan adapter email tidak mencetak email/reset token ke console. |
| Bypass CMS melalui Supabase | Role runtime tidak dapat CREATE schema; anon tidak dapat SELECT users. Request Data API pada schema payload/users mendapat 406/PGRST106. |

Ada **satu Admin demo lokal**, bukan identitas Admin resmi organisasi. Email/password login dibaca dari BOOTSTRAP_ADMIN_EMAIL dan BOOTSTRAP_ADMIN_PASSWORD dalam `.env.local`; tidak dicetak pada laporan/chat/Git. PAYLOAD_SECRET tetap terpisah. Keputusan bootstrap tidak membuat password default tetap pada source.

Skrip bootstrap dijalankan melalui runner `payload run`. Source adapter versi ini mempertahankan koneksi heartbeat dan destroy tidak mengakhiri seluruh pool; skrip Node mandiri sempat tidak keluar setelah akun berhasil dibuat. Runner CLI resmi mengakhiri proses setelah operasi yang di-await selesai dan mengembalikan exit 1 untuk kegagalan. Setelah diperbaiki, bootstrap ulang keluar normal tanpa memodifikasi akun. Tidak mengubah source dependency atau mengabaikan error bootstrap.

## Audit dependency dan batas kelulusan

Audit awal menemukan temuan DOMPurify critical/high di editor Monaco panel Admin. Override terpatok **DOMPurify 3.4.17** diterapkan; audit akhir: **0 critical, 1 high, 1 moderate, 1 low**. Audit tidak dinyatakan bersih.

- High: [graphql-scalars PhoneNumber ReDoS](https://github.com/advisories/GHSA-x8rm-f576-gq67), ditarik integrasi GraphQL Payload. GraphQL dimatikan pada config dan tidak didaftarkan sebagai route; POST /api/graphql terbukti 404. Scalar PhoneNumber tidak digunakan oleh schema users. Jalur ini tidak aktif pada T006; setiap pengaktifan GraphQL harus memperbarui dependency ke versi patched terlebih dahulu. Tidak memaksa override major graphql-scalars tanpa bukti kompatibilitas upstream.
- Moderate: [esbuild dev-server](https://github.com/advisories/GHSA-67mh-4wv8-2f99) pada tooling turunan; tidak menjalankan server esbuild. Development memakai Next/Turbopack, bukan endpoint serve esbuild.
- Low: [deepmerge prototype poisoning](https://github.com/advisories/GHSA-gcqx-w48m-w2h4), belum tersedia patch pada hasil audit; tetap dicatat untuk T053. Tidak menyimpulkan seluruh aplikasi sudah lulus audit keamanan.

Dua warning advisor lama pada public.rls_auto_enable tetap sama, tanpa warning baru untuk schema privat. TLS client→pooler tetap diverifikasi; batas TLS internal provider dari T005 belum diubah. T007 masih harus membuktikan pencabutan akses akun nonaktif pada sesi lama, Admin terakhir, reset lokal dan audit perubahan akun. T008 menyediakan harness/fixture lintas pengguna; T053 menutup audit lebih luas.

**T006 selesai; CP-02 ditinjau; T007 siap dikerjakan.** Ini bukti CMS localhost, bukan persetujuan deployment produksi.
