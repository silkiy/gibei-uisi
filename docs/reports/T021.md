# T021 / CP-07 — Konflik keputusan dan audit

Selesai 31 Oktober 2026. Dua request ditahan pada advisory lock PostgreSQL yang sama; tes memastikan keduanya benar-benar mengantre di `pg_locks` sebelum barrier dilepas. Dua keputusan publish/request-revision atas satu snapshot menghasilkan tepat satu 200 dan satu 409, satu kenaikan lockVersion dan satu audit keputusan. Approval lama tetap ditolak. Publish konten dependen bersamaan dengan withdrawal target wajib juga hanya mengizinkan satu hasil kompatibel. Dua edit dari versi sama menghasilkan satu commit dan satu konflik.

Audit menyimpan actor, timestamp, revision/edit version, perubahan state dan alasan revisi. POST/PATCH/DELETE audit ditolak untuk Admin maupun Media; role runtime juga tidak memiliki UPDATE/DELETE/TRUNCATE pada tabel audit. Harness menghentikan dan menjalankan ulang server produksi uji, login kembali, lalu membandingkan seluruh audit sebelum/sesudah restart dan jumlah lewat API. Data tidak hilang atau berubah.

Verifikasi: 33 integration, Local API guards dan audit persistence setelah restart lulus; build produksi terisolasi, lint dan TypeScript lulus. Fault publish/storage/audit dan CAS dari suite sebelumnya tetap lulus. Tidak ada perubahan schema atau pelonggaran guard untuk meloloskan tes. CP-07 ditinjau; selanjutnya T022 menghubungkan layanan ini ke UI. Kelulusan ini membuktikan skenario editorial yang diuji, bukan audit keamanan seluruh operasi internal dependency/autentikasi.
