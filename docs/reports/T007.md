# T007 — Pengelolaan akun dan sesi

Tanggal: 30 Oktober 2026. Lingkup: PRD §8.2, AC-17. T007 dipecah menjadi T007.1 (kebijakan/transaksi), T007.2 (audit/migration), dan T007.3 (pengujian API, Local API, browser, serta dokumentasi), karena melampaui lima berkas.

## Perilaku

- Admin aktif dapat membuat akun serta mengubah nama, email, role, status dan password lewat Users. Media hanya membaca akunnya sendiri; tidak dapat membuat/mengubah akun, termasuk password. Password lokal 16–256 karakter, di-hash oleh Payload; pendaftaran publik dan recovery email tetap ditutup.
- Setiap mutasi akun mengambil PostgreSQL advisory transaction lock `(697815, 7)` sebelum membaca actor/target. Actor dibaca ulang dalam transaksi. Penurunan/nonaktif Admin terakhir menghasilkan 409; perubahan massal ditolak. Penghapusan akun ditolak untuk semua peran sesuai batas MVP; gunakan nonaktif.
- Autentikasi JWT Payload 3.92 membaca user dan session terbaru dari database. Wrapper strategi pada onInit menolak status nonaktif sebelum CMS/API menerima identitas tersebut. Perubahan role/status/email atau password mencabut seluruh sesi target dalam transaksi yang sama, termasuk sesi pelaku bila mengubah akun sendiri; login ulang diperlukan.
- `account-audit` menyimpan actorId/targetId, aksi, timestamp, serta snapshot nama/email/role/status sebelum/sesudah. Password reset hanya menyimpan jenis aksinya. Tidak ada password, hash, salt, cookie atau token dalam snapshot. Admin dapat membaca; CMS/API/Local API biasa tidak dapat menambah/mengubah/menghapus riwayat.
- Penulisan audit memakai capability Symbol internal dan req transaksi yang sama. Runtime database tidak memiliki UPDATE/DELETE/TRUNCATE pada audit; anon/authenticated/PUBLIC tidak mendapat akses tabel. Akun dan audit harus commit/rollback bersama. Akun bootstrap lama T006 tidak diberi riwayat palsu secara retroaktif.
- Manual unlock bawaan dan recovery token ditolak juga lewat hook Local API. Lock login berakhir otomatis setelah 15 menit; reset password lokal bukan pengganti menunggu lock tersebut. Tidak ada pemulihan operator jika satu-satunya Admin kehilangan kredensial dalam lingkup tugas ini.

## Bukti pengujian

Suite terarah `pnpm test:accounts` menggunakan schema privat sementara dengan nama `payload_test_t007_<12 hex>`, disediakan kosong oleh operator database dan dimiliki gibei_migrator. Bukan schema `payload`, bukan akun Admin pengembangan, bukan database layanan Supabase. Fixture memakai migration yang ditinjau, bootstrap resmi, password acak, runtime biasa, dan server loopback port 3200. Cleanup hanya schema yang telah lulus pemeriksaan nama/ownership/kosong. Kebutuhan harness umum dan browser fixture T008 tetap terpisah.

Hasil suite API:

- Pengunjung dan Media ditolak saat create/update/reset; pembacaan akun lain ditolak. Internal credential fields dan password pendek ditolak.
- Admin dapat create, menonaktifkan/mengaktifkan, reset password dan mengganti role. Password lama gagal, password baru dapat login; cookie lama tetap ditolak setelah reaktivasi.
- Nonaktif: request berikutnya ditolak, `/me` tidak mengembalikan identitas dan refresh/login ditolak.
- Pemeriksaan status terbaru juga lulus dengan record sesi masih tersimpan (fixture SQL), sehingga penolakan tidak hanya bergantung pada penghapusan sesi. Reset password Admin sendiri juga mencabut cookie yang sedang dipakai; login ulang dengan password baru berhasil.
- Dua self-demotion/nonaktif Admin bersamaan: **200 dan 409**, tersisa tepat **satu Admin aktif**.
- Kegagalan INSERT audit yang disimulasikan menghasilkan 500 dan perubahan nama akun rollback; jumlah audit tidak berubah. Izin dipulihkan di fixture.
- Create/update/delete audit lewat API ditolak. UPDATE/DELETE/TRUNCATE SQL sebagai runtime menghasilkan 42501. Snapshot tidak mengandung kredensial.
- Metadata akun pengembangan sebelum/sesudah sama. Fixture dibersihkan setelah suite.
- Local API default/overrideAccess tanpa actor tidak dapat create/update/delete akun atau memalsukan audit melalui flag JSON. Recovery/unlock tetap ditolak dan mutasi tanpa transaksi menghasilkan 503.

Pemeriksaan akhir lulus: lima tes kebijakan akun, tiga tes konfigurasi database, `lint`, `typecheck`, production `build`, `db:verify`, serta `test:cms` pada hasil produksi. Migration `20261030_153435_account_controls` tercatat Ran=Yes, batch 2. Edge 156.0.4314.50 terisolasi memverifikasi login, form create Users (role/status), Change Password, audit tanpa tombol create, logout dan halaman publik; pageErrors=0. Bukti lokal berada di `artifacts/t007-user-form.png` dan `artifacts/t007-account-audit.png` (diabaikan Git). Query akhir mengonfirmasi nol schema uji tersisa dan satu Admin aktif pengembangan. Pemindaian staged diff dan 62 file build statis tidak menemukan secret environment. Perubahan whitespace pengguna pada migration T005 tidak ikut commit.

## Temuan dan keputusan implementasi

1. Validasi credential internals harus dilakukan pada beforeOperation (input mentah), karena field defaults Payload menambahkan sessions sebelum beforeValidate. Tes bootstrap terisolasi menemukan dan memverifikasi koreksi ini.
2. Context Symbol diteruskan eksplisit ke nested Local API; `createLocalReq` memperlakukan context dengan nol string-key sebagai kosong. Tidak menggantinya dengan flag JSON yang dapat dipalsukan.
3. Document lock bawaan Payload melakukan pembacaan di luar req transaksi. Dengan pool max=3, dua transaksi akun menyebabkan starvation/timeout. `lockDocuments=false` hanya pada Users dan audit, karena akun sudah diserialisasi lewat advisory lock dan audit tidak dapat diedit. Tidak menaikkan ukuran pool; locking editorial tugas berikutnya tetap harus dibuktikan tersendiri.
4. Role migrator tidak mendapat CREATE pada database untuk membuat schema. Provisioning schema uji melalui integrasi Supabase mempertahankan batas least privilege.

## Batas dan rujukan

T008 menyiapkan harness unit/integration/e2e umum dan fixture dua Media; T007 ini belum membuktikan workflow editorial. Tidak ada deployment produksi atau penggantian kredensial Admin pengembangan. Audit dependency diperiksa ulang: critical=0, high=1, moderate=1, low=1, sama dengan T006; GraphQL tetap nonaktif. Temuan dependency, TLS internal pooler, dan dua warning advisor bawaan dari T006/T005 tetap terbuka untuk T053. Advisor diperiksa ulang dan tidak menemukan temuan baru terkait audit privat: [anon SECURITY DEFINER](https://supabase.com/docs/guides/database/database-linter?lint=0028_anon_security_definer_function_executable), [authenticated SECURITY DEFINER](https://supabase.com/docs/guides/database/database-linter?lint=0029_authenticated_security_definer_function_executable).

Sumber implementasi: [Payload collection hooks](https://payloadcms.com/docs/hooks/collections), [transaksi dan req](https://payloadcms.com/docs/database/transactions), serta source/deklarasi paket Payload 3.92.0 dan guide Route Handlers Next 16.4.2 yang terpasang. Perilaku JWT, sessions, Local API context dan document lock diperiksa pada source versi terpasang lalu diuji langsung.
