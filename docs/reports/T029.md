# T029 — Periode organisasi melalui review

Status verifikasi akhir dicatat pada [T030](T030.md).

- `organizational-periods` menyimpan label unik tetap, owner/assignee, pointer kerja/publik dan lockVersion. `period-revisions` menyimpan tanggal sebagai teks kalender ISO `YYYY-MM-DD`, dengan validasi kalender sebenarnya serta start <= end; tidak melewati konversi timezone.
- Admin membuat identitas/penugasan. Media berizin menyimpan draft, submit, membaca catatan revisi dan membuat revisi baru. Publish, minta revisi, withdrawal dan hapus draft melalui perintah domain; publish hanya Admin pada submission/digest/editVersion yang tepat.
- `organization-reviews` menyimpan manifest dan keputusan per jenis/entitas. `organization-audit` append-only. Keduanya dipakai juga oleh divisi tanpa mengubah alur Pages/artikel yang telah terbukti. Semua mutasi memakai transaksi dan lock graph yang sama.
- `/api/public/organization/periods` hanya mengembalikan label dan tanggal dari versi approved/published. Revisi kerja tidak mengubah hasil publik. Pilihan periode aktif tidak ditambahkan; tetap T032.
- Penghapusan generik ditolak. Perintah Admin `delete-draft` membuat tombstone hanya untuk draft yang belum disetujui, tanpa review pending atau referensi. Sejarah/audit dipertahankan. Referensi seluruh revisi divisi menahan penghapusan; divisi yang masih terbit menahan withdrawal periode.
- Relasi periode opsional pada profil divisi memungkinkan konteks program per periode tanpa mengubah nama delapan divisi. Submit/publish divisi menolak target periode yang belum terbit. T031 wajib memperluas pemeriksaan dependensi untuk Members ketika modul tersebut ditambahkan.

Tes: duplikasi label, tanggal rollover/terbalik, izin/spoofing/ID tebakan, review ulang, stale decision, dua edit bersamaan, snapshot publik, dependensi divisi, tombstone, serta rollback saat audit gagal. Browser membuat dan menerbitkan satu periode melalui CMS.
